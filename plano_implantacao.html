1. Resumo Executivo & Arquitetura Geral

Este projeto estabelece uma infraestrutura corporativa robusta para monitoramento contínuo de conectividade, vazão (Download/Upload em Mbps) e latência de gateway (Ping em ms) entre data centers e filiais. A arquitetura é 100% desacoplada: os agentes desktop operam autonomamente com banco local e reportam métricas via HTTPS ao nó central em formato de séries temporais de alta granularidade.

🖥️ Client Probe (Desktop Windows)

  • • Framework: Wails v2 + Go 1.22 (Dark Theme)
  • • Ciclo: Goroutine Ticker (1 hora) + Disparo Manual
  • • Resiliência: SQLite Local (probe_local.db)
  • • Frontend: Chart.js (Download, Upload e Ping)
POST HTTPS

🐧 Central Server (Linux Debian)

  • • Backend: Go 1.22 com Driver Oficial Mongo v2
  • • Time Series: network_central.metrics
  • • Config: timeField: timestamp | granularity: hours
  • • Dashboard: Web responsivo com filtros por nó
2. Contrato da API de Telemetria (POST /api/v1/metrics)

A comunicação entre cada sonda e o servidor central ocorre via HTTPS utilizando o cabeçalho Authorization: Bearer <api_token> e payload estruturado em JSON com precisão decimal: 

{
  "node_id": "minipc-dc-01",        "location": "Guarapuava-DC1",
  "timestamp": "2026-09-11T15:00:00Z",
  "download_mbps": 850.5,       "upload_mbps": 720.0,       "ping_gateway": 1.2
}
3. Detalhamento Técnico dos Componentes

🖥️ Client Desktop (/client-probe) Wails v2

  • Configuração (config.json): Parâmetros de nó, servidor e token carregados na inicialização e editáveis em tempo de execução via UI.
  • Agendamento Automático: Goroutine em segundo plano executando testes a cada 1 hora sem bloqueio da interface gráfica.
  • Medição Real de Rede: Ping para o gateway padrão via ICMP nativo / TCP socket e cálculo de throughput Download/Upload em Mbps.
  • Persistência Local (SQLite): Histórico gravado em probe_local.db para operação offline resiliente.
  • Interface Visual: Dark slate com acentos em ciano e roxo, gráficos de 24h, status badge dinâmico e botão com spinner.

🐧 Central Server (/central-server) Debian / Mongo v2

  • Driver Oficial MongoDB v2: Conexão via go.mongodb.org/mongo-driver/v2/mongo com pooling e retry automático.
  • MongoDB Time Series: Coleção nativa metrics configurada com timeField: "timestamp", metaField: "metadata" e granularity: "hours".
  • API REST com Bearer Auth: Middleware de validação de token e endpoint analítico GET /api/v1/dashboard/metrics.
  • Dashboard Web Integrado: Servido em GET / com seletor de nós, cartões de resumo e comparativo entre data centers.
  • Produção Debian: Docker Compose, Dockerfile multi-stage e service unit para systemd.

6. Critérios de Qualidade e Resiliência Operacional

🛡️ Resiliência e Tolerância a Quedas

• Quedas de internet na ponta não travam a sonda desktop: medições ficam retidas no SQLite local como synced=0.
• Servidor Central opera em modo não-bloqueante com timeout de 5s no MongoDB e graceful shutdown em sinais SIGINT/SIGTERM.

⚡ Performance e Escalabilidade

• O modelo MongoDB Time Series compacta leituras por hora e data center, reduzindo em até 70% o uso de disco.
• Frontend do Client e do Servidor utilizam Chart.js otimizado para renderização de até centenas de pontos sem perda de fluidez.

1 Visão Geral: O Que é LLDP e Qual Seu Propósito?

O LLDP (Link Layer Discovery Protocol), padronizado pelo IEEE 802.1AB, é um protocolo de descoberta de vizinhança que atua na Camada de Enlace (Camada 2 do Modelo OSI). Ele permite que dispositivos de rede (switches, roteadores, firewalls, telefones IP e servidores) anunciem periodicamente suas identidades, capacidades operacionais e detalhes da porta física aos seus vizinhos diretamente conectados.

Ao contrário de protocolos roteados ou de camada superior (como SNMP, ICMP ou HTTP), o LLDP não depende de endereçamento IP configurado nem de credenciais de login. Ele opera de forma estritamente unidirecional e passiva: o switch transmite anúncios em broadcast/multicast Layer 2 sem exigir handshake ou resposta da ponta receptora.

Estrutura do Frame LLDP

  • EtherType: 0x88CC
  • Endereços MAC Multicast Destino:
    • 01:80:C2:00:00:0E (Nearest Bridge)
    • 01:80:C2:00:00:03 (Nearest Non-TPMR)
    • 01:80:C2:00:00:00 (Nearest Customer)
  • Intervalo Típico de Transmissão: 30 a 60 segundos.
  • Encapsulamento: TLV (Type-Length-Value).

O Equivalente Cisco: CDP

  • Protocolo: Cisco Discovery Protocol (CDP).
  • EtherType / SNAP: 0x2000.
  • MAC Destino: 01:00:0C:CC:CC:CC.
  • Objetivo: Proprietário Cisco com finalidade idêntica ao LLDP (mapeamento de portas, VLANs de voz e switches).
  • Tratamento na Probe: A sonda trata frames LLDP e CDP de forma unificada.

Estrutura TLV (Type-Length-Value) Obrigatória e Opcional

Tipo TLV Nome Informação Extraída pelo Polling App Campo no Payload JSON
TLV 1 Chassis ID MAC ou Hostname do chassi do Switch switch_name
TLV 2 Port ID Identificador da interface física (ex: GE1/0/24, Gi0/1) switch_port
TLV 3 Time To Live (TTL) Tempo de expiração da informação (ex: 120s) Utilizado internamente
TLV 4 Port Description Descrição administrativa ou nome do link switch_model / Descrição
TLV 5 System Name Hostname do Switch (ex: SW-CORE-FLOOR2) switch_name
TLV 6 System Description Modelo de hardware e versão do SO (ex: Huawei V200R021) switch_model (normalizado)
TLV 127 Org-Specific (802.1) Port VLAN ID (PVID) da interface vlan

2 O Que é o PSDiscoveryProtocol e Como Ele Funciona no Windows?

O sistema operacional Windows para estações de trabalho (Windows 10 e 11) não expõe nativamente APIs de usuário simples para ler frames LLDP/CDP de switches. O recurso nativo MSFT_NetLldpAgent só existe com DCB (Data Center Bridging) ativado no Windows Server e quase sempre está inativo ou inacessível em desktops padrão.

O PSDiscoveryProtocol é um módulo especializado de automação PowerShell (criado pela comunidade de engenharia de redes) projetado para resolver exatamente este gargalo. Ele atua capturando pacotes brutos diretamente da placa de rede ativa durante uma janela de tempo e decodificando os bytes binários das PDUs LLDP e CDP.

3 A Implementação do LLDP no Código do Polling App

No Polling App, a lógica de descoberta de switch é centralizada no arquivo client-probe/lldp.go através da função DiscoverSwitchLLDP(ctx context.Context) SwitchInfo. O sistema foi desenvolvido com resiliência total para rodar em estações Windows corporativas heterogêneas sem intervenção manual do usuário.

A. Autoinstalação e Resiliência do Módulo PowerShell

Se o agente estiver rodando em uma máquina nova onde o PSDiscoveryProtocol ainda não foi instalado, o próprio script em runtime realiza o provisionamento sem interromper a execução: 

# 1. Garante que o módulo PSDiscoveryProtocol esteja disponível (instala automaticamente)
if (-not (Get-Module -ListAvailable -Name PSDiscoveryProtocol)) {
    try {
        [Net.ServicePointManager]::SecurityProtocol = [Net.SecurityProtocolType]::Tls12
        Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass -Force
        Install-PackageProvider -Name NuGet -MinimumVersion 2.8.5.201 -Force -Scope CurrentUser | Out-Null
        Install-Module -Name PSDiscoveryProtocol -Scope CurrentUser -Force -SkipPublisherCheck -AllowClobber | Out-Null
    } catch {}
}
Resiliência Operacional
O parâmetro -Scope CurrentUser dispensa elevação administrativa para baixar o módulo do repositório PSGallery. A definição de ExecutionPolicy Bypass no escopo Process assegura que políticas restritivas do PowerShell local não bloqueiem a execução do script.

B. Captura Passiva de Tráfego L2

Com o módulo carregado, a sonda chama Invoke-DiscoveryProtocolCapture por 35 segundos. Como switches corporativos transmitem anúncios a cada 30 segundos, uma janela de 35s garante com altíssima probabilidade a captura de pelo menos um frame completo: 

$capture = Invoke-DiscoveryProtocolCapture -Duration 35 -Force
$rawList = $capture | Get-DiscoveryProtocolData

C. Algoritmo Crítico: Filtragem Anti-Falso Positivo de Telefones VoIP

Em redes corporativas, é comum que computadores estejam conectados na porta PC Port de um telefone VoIP (Cisco CP-78xx/88xx), que por sua vez se conecta à tomada de parede do switch. Como o telefone IP também anuncia CDP/LLDP na interface do PC com nomes de dispositivo como SEP001122334455 (Skinny Client Control Protocol com MAC do telefone), uma leitura ingênua identificaria o telefone como se fosse o switch de borda.

O Polling App implementou uma filtragem estrita e inteligente para eliminar esse ruído: 

# Filtra ESTRITAMENTE apenas SWITCHES de rede reais, descartando telefones VoIP
$realSwitches = @($rawList) | Where-Object {
    $dev = if ($_.Device) { [string]$_.Device } elseif ($_.SysName) { [string]$_.SysName } else { "" }
    $model = if ($_.Model) { [string]$_.Model } elseif ($_.Type) { [string]$_.Type } else { "" }
    
    # Descarte expresso de identificadores SEP e modelos telefônicos
    $dev -notmatch '^SEP[0-9A-Fa-f]{12}' -and $model -notmatch 'Phone|Telefone|VoIP'
}

D. Sistema de Pontuação Heurística (Heuristic Scoring)

Caso múltiplos dispositivos transmitam frames LLDP válidos, a sonda executa uma ordenação baseada em pontuação ponderada para eleger o switch mais provável:

Critério de Avaliação Expressão / Condição Pontos Motivo Técnico
VLAN Corporativa $vlan -gt 0 +50 pts Switches gerenciáveis anunciam a VLAN da porta do usuário (802.1Q).
Padrão de Porta Enterprise Port -match '^(GE|Gi|Fa|Te|Eth|Gigabit|Port-channel)' +30 pts Nomenclatura típica de portas físicas em switches de acesso empresariais.

E. Normalização e Reconhecimento de Modelos Corporativos

Identificadores brutos de switches Huawei (ex: S5735-L24T4S-A-V2) são normalizados antes do envio ao servidor central, garantindo dashboards limpos e legíveis: 

if ($swModel -match 'S5735-[A-Za-z0-9\-]+') {
    $swModel = "Huawei CloudEngine " + $Matches[0]
} elseif ($swModel -match 'Huawei|CloudEngine' -and $swModel -notmatch 'CloudEngine') {
    $swModel = "Huawei " + $swModel
}

4 Ciclo de Vida da Descoberta, Caching e Otimização

Executar uma captura de pacotes de 35 segundos em toda medição de rede seria inviável, pois atrasaria os testes de velocidade (Download/Upload/Ping) e consumiria recursos desnecessários de CPU. O Polling App adota uma estratégia de descoberta em segundo plano com persistência em cache.

Fluxo de Descoberta no Startup da Aplicação (`app.go`)

Ao iniciar o Client-Probe (Go + Wails), uma goroutine em background é disparada imediatamente, executando até 3 ciclos de busca progressivos:

  1. Tentativa 1 (75 segundos): Timeout estendido para acomodar possíveis atrasos no timer do switch ou instalação inicial do módulo PowerShell.
  2. Tentativas 2 e 3 (50 segundos cada): Repetição caso a porta ainda estivesse negociando ou o switch estivesse em janela entre beacons.
  3. Parada Imediata: Assim que um switch real é detectado (sw.IsRealSwitch() == true), o loop é interrompido com sucesso e o status é emitido em tempo real para a interface gráfica (Wails).

Estratégia de Cache e Persistência SQLite (`storage.go` & `probe.go`)

  • Persistência em Disco: Toda medição que inclui informações de switch é armazenada na tabela local SQLite.
  • Reaproveitamento nas Medições Periódicas: Na execução da rotina MeasureAll(ctx, cfg, knownSwitch), se o switch já for conhecido e for um switch real (knownSwitch.IsRealSwitch() == true), a sonda não roda o PowerShell novamente, economizando 35 segundos e entregando o teste de velocidade instantaneamente.
  • Fallback Histórico no Boot: Se o app for reiniciado sem rede ou antes do primeiro frame LLDP chegar, o método storage.GetLastValidSwitchInfo() recupera o último switch corporativo válido registrado no banco de dados local.

5 Visualização e Consumo: Frontend e Servidor Central

As informações extraídas pelo LLDP são sincronizadas ponta a ponta e exibidas em dois níveis:

Interface Local (Client-Probe)

No card "Conexão de Switch (LLDP)" da interface Wails da máquina do usuário:

  • Switch: Ex: SW-DIST-A-ANDAR2
  • Porta: Ex: GigabitEthernet0/0/14
  • VLAN: Ex: VLAN 100
  • Modelo: Ex: Huawei CloudEngine S5735

Dashboard Central (Central-Server)

Ingerido via endpoint POST /api/metrics e salvo no MongoDB:

  • Identificação imediata da porta física e switch de cada nó corporativo.
  • Detecção automática de computadores trocados de mesa ou porta.
  • Correlação entre quedas de performance e portas de switch com erro de CRC ou limitação de negociação (100Mbps vs 1Gbps).

6 Guia de Diagnóstico e Resolução de Problemas (Troubleshooting)

Sintoma Observado Causa Raiz Mais Provável Ação Corretiva Recomendada
"Aguardando frame LLDP..." contínuo O switch conectado não está com LLDP ativado ou a interface está em um switch não gerenciável (dumb switch). No switch de acesso, habilitar LLDP:
• Huawei: lldp enable
• Cisco: lldp run ou cdp run
• Aruba: lldp run
Dispositivo Conectado via Wi-Fi Access Points Wi-Fi em geral não encaminham frames LLDP de switches cabeadas via rádio 802.11. Comportamento esperado em redes sem fio. A probe entra em fallback seguro e mantém as medições de IP e velocidade normais.
Permissão PowerShell Política de execução restrita por GPO de domínio impedindo execução de scripts. O código utiliza -ExecutionPolicy Bypass no processo da probe. Caso bloqueado por AppLocker/WDAC, homologar o binário da probe.
Aparece Telefone IP em vez do Switch Telefone IP corporativo com formato de nome fora do padrão SEP usual. O regex no lldp.go já exclui ^SEP[0-9A-Fa-f]{12} e modelos com Phone|VoIP. Se surgir novo modelo, adicionar o padrão ao filtro.
